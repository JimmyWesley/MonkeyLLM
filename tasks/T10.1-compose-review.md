# T10.1 Compose with review: see the passport before the forest keeps it

## Goal

Close the one acceptance criterion T10 could not: the Ingest **Write** tab
planted the node and *then* showed what the Curator had made of it. Turn
`compose` into two calls one that stages and returns the draft, one that
accepts it so the summary and the link proposals are decided before they
are facts.

## Context

Curation is the only ingest step whose output somebody may want to see
first. A summary is the scent every later hop navigates by (A.4); a
proposal is what the Ranger spends the next month promoting or pruning
(H.2). Both are cheap to fix in a draft and expensive to fix in a node that
already exists, already has a commit, and may already have been read.

That is contract, so it needed a spec version before code:
**`docs/monkeyllm-spec-v0.24.md`, J.8.1**, criterion **F.27**.

## Steps

1. ~~**Spec bump first**~~ v0.24: J.8.1 two-phase compose, F.27, CLAUDE.md
   and `tasks/README.md` repointed.
2. ~~**Engine: a Gardener that cannot write.**~~ `Gardener(dry_run=True)`
   guards every write site it owns plant, branch creation, body cache,
   archived bytes, passport refresh, rollup, config and collects the
   passports it would have planted in `IngestReport.drafts`.
3. ~~**Station: the two phases.**~~ `stage: true` previews; a `draft` body
   accepts. `monkeyllm_station/compose.py` holds both halves: the reviewable
   projection (with each proposed target's *title*) and the approval hook.
4. ~~**Studio: the review card.**~~ The Write tab's primary action is now
   *Review draft*; publishing happens from the card, which shows the id,
   parent, type, an editable summary with the 60-token counter, editable
   tags, and one checkbox per proposal. Discard keeps the composed text.
5. ~~i18n en/pt/es for every new string; `tests/test_station_compose_review.py`.~~

## Acceptance criteria

- [x] Spec section merged before any endpoint code; normative version resolved.
- [x] A staging call leaves `git rev-parse HEAD` unchanged, plants nothing,
      creates no branch, writes no body cache, touches no `gardener.yaml`,
      and reports no commit sha to the audit log.
- [x] The previewed id is the id the accepting call plants.
- [x] The planted summary is the approved text, not a re-curated one.
- [x] A returned draft is re-validated: links that name a branch, a
      non-existent node, an out-of-scope node, the node itself, its parent,
      a rel other than `related-to`, or a fourth proposal are dropped, and
      every survivor is written at confidence 0.3.
- [x] `stage` on `adopt`/`sync`/`upload` is refused with the reason; a body
      carrying both `stage` and `draft` is refused.
- [x] Staging still requires `ingest` and is refused on a read-only Station.
- [x] i18n complete in all three languages; Studio builds; no console errors.

## Out of scope

Review for batch modes (`adopt`/`sync`/`upload`) a batch has no single
decision to make, and a per-file queue is a different feature. Editing the
composed *text* from the review card (Discard returns to the composer, which
is where the text belongs). Server-side draft storage: the review is
stateless because every field has to be re-validated on the way back
regardless of who held it in the meantime.

## Outcome

Contract first, then engine, then host, then console.

The dry run is a property of the **object**, not of a call: `Gardener(...,
dry_run=True)` cannot write by any path it offers. A flag passed per call is
forgotten by the next call somebody adds, and the guarantee this exists to
give "nothing was written" has to hold for the object.

Accepting walks the *same* pipeline. The approved passport enters as an
ordinary `on_curate` hook (G.4.3), so the converter, the content policy, the
plant and the commit are the ones every adopted file gets. A second write
path that planted from a draft directly would be a second definition of what
a passport is, and nothing would keep the two honest.

`tests/test_station_compose_review.py` (21 tests) covers F.27. Most of them
are negative nothing planted, nothing committed, no branch, no cache, no
config because those are exactly the assertions a later refactor breaks
quietly: a stray write still returns 200 and still looks right in the report.

Verified against a live Station with a stub ingest model, so the review card
was exercised with real proposals rather than an empty list: three offered,
one unticked, and the planted node carried the other two at 0.3 with their
notes, under the summary as edited. One commit for the pair of calls, and
the audit log shows the staging call with no sha.

**One defect found in that pass, in code written for this task:** the review
card was keyed on the draft id, and staging the same title twice returns the
same id so editing the text and reviewing again brought back the *previous*
review's summary, tags and unticked boxes. A reviewer would have approved a
passport they never saw. Keyed on a staging counter instead.
